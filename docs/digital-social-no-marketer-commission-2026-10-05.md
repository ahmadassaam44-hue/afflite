# الرقمي والسوشيال للمسوقين: شيل «عمولتك المضافة للقطعة / سعر العميل / ربحك» (2026-10-05)

## المطلوب
خانة **«عمولتك المضافة للقطعة (ج.م)»** ومعاينة **«سعر العميل: … / ربحك: +…»** كانت بتظهر للمسوقين على المنتجات الرقمية
وخدمات السوشيال ميديا. دي اتشالت خالص من المنصتين دول — سعرهم بقى **سعر المصدر بالظبط** ومفيش أي إضافة أو «سعر اتفاق».

## اللي اتغيّر

| الملف | التغيير |
|---|---|
| `config.php` | `marketer_store_product_comm()` بترجّع **0** لأي منصة رقمية/سوشيال (مهما كان محفوظ في متجر المسوق أو الجلسة أو `?comm` في الرابط) — `server_order_line()` بقى `min_sale = max_sale = سعر المصدر` وللمنصتين دول مفيش سعر اتفاق ولا عمولة مضافة — `marketer_effective_price()` بتتجاهل أي عمولة صريحة — `landing_page_url()` مبقتش تحط `comm` في الروابط |
| `dashboard/marketer.php` | كروت الكتالوج: مفيش خانة عمولة ولا «سعر العميل / ربحك» للرقمي/السوشيال، وبدلها سطر «سعر ثابت: … — من غير عمولة مضافة». جدول متجري: خانة العمولة بقت «سعر ثابت — من غير عمولة مضافة»، وسعر البيع للعميل = سعر المصدر. جدول الروابط السريعة: الخلية «— سعر ثابت». ترتيب «أعلى عمولة مضافة» اتشال من تبويبات الرقمي/السوشيال. أي حفظ لمنتج رقمي بيفرض `extra_comm = 0` وأي إشعار للإدارة مبيلاقش «عمولة مضافة» |
| `dashboard/layout.php` + `index.php` | كارت المنتج للمسوق المسجّل مبيلاقش بلوك «عمولتك / هبوط» للمنتجات الرقمية والسوشيال |
| `store.php` | المتجر المستقل: العمولة المخزنة قديمًا بتتجاهل للرقمي/السوشيال (السعر المعروض = سعر المصدر)، وأي تعديل عمولة لمنتج رقمي بيتصفّر |
| `dashboard/orders.php` | الأوردر المسجَّل بيسجّل العمولة المضافة اللي اتحسبت فعلاً (صفر للرقمي/السوشيال) بدل القيمة المبعوتة |
| `assets/ui.js` | بادج وتوست «حفظ بمتجري» بقوا «في متجرك / تم حفظ المنتج» بدل «(+0 ج.م)» لما مفيش عمولة |

## الفرق للمسوق
- المنتجات **(فيزيكال)**: زي ما هي — عمولة مضافة + سعر عميل + ربحك + ترتيب بأعلى عمولة.
- **الرقمي والسوشيال ميديا**: سعر ثابت = سعر المصدر، مفيش عمولة مضافة ولا سعر اتفاق، وبالتالي مفيش ربح إضافي من الإضافة
  على المنصتين دول (العمولة الوحيدة للمسوق كانت الإضافة نفسها، و`product_commission_unit` بترجّع 0 ليهم أصلاً).

## التحقق (PHP 8.3 / php-wasm على نسخة معزولة)
1. **48 ملف PHP** بدون أخطاء صياغة + `node --check assets/ui.js` ناجح.
2. **كروت المسوق**: تبويب الرقمي وتبويب السوشيال → `عمولتك المضافة للقطعة = 0`، `data-card-markup = 0`، `سعر العميل = 0`، `ربحك = 0`، وسطر «من غير عمولة مضافة» = 25 كارت. تبويب المنتجات → لسه فيه 24 خانة عمولة (زي ما هو).
3. **متجر المسوق**: صف `social#hevo-15` (وكان فيه عمولة قديمة 7.5 محفوظة) → «سعر ثابت — من غير عمولة مضافة» وسعر البيع للعميل **0.67** بدل 8.17.
4. **اختبار مباشر على الدوال**: `marketer_store_product_comm = 0` للرقمي والسوشيال رغم وجود قيمة في الجلسة، `marketer_effective_price(explicit 9) = سعر المصدر`، `server_order_line(100, extra 9)` → `unit = 0.67, markup = 0`، وللمنتج الفيزيكال `marketer_effective_price(explicit 10)` لسه بتضيف (560) والرابط لسه فيه `&comm=10`.
5. **حفظ منتج رقمي** بـ `extra_comm=9` → المتجر بيتخزن `extra_comm = 0`، وحفظ منتج فيزيكال بـ `extra_comm=25` → بيتخزن 25.
6. **أوردر حقيقي من صفحة الطلب** (سوشيال + رقمي) مع عمولة قديمة محفوظة: `unit = سعر المصدر`، `total = سعر المصدر`، `m_earn = 0`، `comm_state = no_commission`.
7. **الرئيسية**: صفحة السوشيال وصفحة الرقمي مافيهم أي «عمولتك / أضف عمولتك / ربحك»، وصفحة الفيزيكال لسه فيها 111 ذكر عمولة للمسوقين (زي ما هو).
8. **المتجر المستقل** (`store.php?store=MKT-TEST`): سعر الخدمة 0.67 بدون أي إضافة، ورابط الطلب من غير `comm`.
