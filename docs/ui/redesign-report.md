## ما تم تنفيذه

- Shell موحّد: Topbar ثابت، عنوان ومسار صفحة، قائمة مستخدم وإشعارات، Sidebar أبيض/سلايت مع active دلالي و`aria-current`، طي 260→72px محفوظ في localStorage.
- Drawer كامل على الموبايل مع labels، حجز scroll الخلفية، focus trap، ESC، الضغط خارج النافذة وإرجاع الفوكس. Bottom nav حسب الدور/تدفق الشراء، مع safe-area.
- مكونات مشتركة: KPI محايد وتعريف قابل للتركيز، جداول sticky مع بحث/حالة/sort/pagination محلي، كروت على الموبايل، تفاصيل قابلة للفتح بدلاً من الأعمدة الزائدة، badges وtimeline وحالات فارغة وloading skeleton.
- تأكيد الإجراءات المالية والمدمّرة **الموجودة أصلاً**؛ الإلغاء لا يرسل الطلب. أسماء الحقول والـhidden inputs والـCSRF ووجهات الطلبات بقيت كما هي.
- نافذة الطلب، المحادثات، clipboard fallback، toast، password feedback، معرض الصور وcarousel أصبحت في `assets/ui.js`، مع إبقاء hooks القديمة.
- العميل: طلبات/تتبع وإلغاء واسترجاع وفق الشروط الحالية، سلة بكروت وstepper وحذف مؤجّل قابل للتراجع، checkout واضح وتحديث عرض رسوم الشحن، دعم وطلب منتج وصورة بمعاينة.
- المسوّق: KPIs محايدة، بديل جدولي للرسم الموجود، Next best action من بيانات المتجر الحالية، كتالوج مطابق للبطاقة العامة، preview العمولة/سعر العميل، روابط مشاركة بنفس ref، ومحرّر هوية بمعاينة محلية وألوان جاهزة وتباين تلقائي. أدوات التسويق الأقل استخداماً داخل details لتخفيف الزحام.
- الأدمن: أقسام منظّمة دون تكرار Hero في كل تبويب، صف «تحتاج مراجعتك»، جداول موحّدة، تنظيم الإعدادات في accordion، وتأكيد تغيير الحالة/السعر/الرصيد/السحب/المدفوعات قبل الإرسال العادي.
- مرور الموقع العام: إصلاح بطاقة المنتج الناقصة، إزالة شريط مبيعات غير صالح ومتغير نسبة غير معرّف، إزالة الخصومات/العدّاد/التوثيق الوهمية من المتجر واللاندنج، إصلاح carousel وروابط الأخطاء في subfolder، وإضافة labels/alt/landmarks/skip links.
- CSS يُحمّل مرة واحدة؛ لا `<style>` في صفحات الواجهة. الألوان من tokens، والأنماط الخاصة باللوحات scoped. استُخرجت التنسيقات المتكررة إلى utilities/مكونات مشتركة، والنسخة القديمة محفوظة في `assets/style.legacy.css`.
- Cairo محلي مع `font-display:swap` (400/600/800)، ونسخة basic Latin محسّنة مع التغطية الكاملة عند الحاجة. أضيفت ملفات الخط وترخيصها فقط إلى قائمة رفع أصول الواجهة.

## قرارات UX

1. الأصفر للعلامة وCTA، لا للخلفيات الكبيرة أو أرقام KPI؛ الأحمر للسالب/الإلغاء فقط.
2. معلومات الجداول الثانوية داخل details، مع نفس controls الأصلية دون نسخ hidden inputs أو تغيير endpoints.
3. الفلاتر والفرز المحلي موصوفة بأنها للصفوف/الصفحة الحالية، حتى لا تُوهم بفرز كامل قاعدة البيانات.
4. المعاينة لا تحفظ تلقائياً؛ حفظ واضح، مع إظهار لون النص المناسب للون المتجر.
5. حذف السلة مؤجّل 5 ثوانٍ قبل زيارة **الرابط القديم**، لتوفير Undo دون إضافة API.
6. خطأ شبكة نافذة الطلب لا يعيد POST تلقائياً؛ تظهر رسالة تحفظ البيانات لتجنب إنشاء طلب مكرر.
7. إجماليات مختلطة العملات تحذيرية؛ لم تضف الواجهة تحويل عملات أو تغيّر أرقام ledger.

## ملاحظات للمراجعة — لم يتغير الباك

- **تعارض عمولة الفريق:** `REF_TEAM_RATE = 0.04` مقابل `REF_TEAM_LABEL = '15%'`. النسبة مخفية عن المسوّقين، والمصدر الوحيد للعرض هو `wf_team_rate_display()` مع TODO صريح؛ الحسابات باقية. يلزم تحديد الصحيح قبل تفعيل عرض النسبة.
- **استعادة كلمة المرور:** `reset.php` يعيد `$valid=false` في مسار GET حتى مع token صالح؛ تأكد ذلك محلياً. لم يُصلح المنطق لأنه خارج نطاق UI.
- **الأدوار:** `ensure_user_affiliate()` يرقّي المشتري إلى مسوّق تلقائياً. هذا يمنع لوحة مشتري مسجّل مستقلة تماماً دون تعديل خلفي. بقي كما هو.
- **GET يغيّر البيانات:** حذف المستخدم/المراجعة/الإشعار، تغيير حالة المسوّق ومعالجة بعض التنبيهات، وread/wishlist/cart GET. تأكيد UI ليس حماية CSRF؛ يحتاج نقل/حماية خلفية منفصلة. تحقق POST الحالي لم يتغير، وفورمات POST المختبرة تحميها CSRF callback الموجودة.
- **السحب:** `balance.php` يجمع المسحوب باستخدام `payout.email` بينما التسجيل الحالي يستخدم `payout.user`. لم يُعاد حسابه؛ الواجهة توجّه للسجل بدلاً من عرض صفر قد يكون مضللاً.
- **العملات:** السجلات القديمة لا تحمل دائماً currency snapshot، والشحن/المحفظة مسجلان بالجنيه مع منتجات خليجية. تعرض الواجهة العملة المتاحة من المنتج وتحذيراً؛ يلزم قرار محاسبي/تحويل رسمي في الباك، وليس جمعاً أو تحويلًا شكلياً.
- **الرفع:** `save_uploaded_image()` الحالي يحتاج مراجعة MIME/محتوى الصورة وحدود الحجم. الواجهة تعرض الأنواع والمعاينة ولا تدّعي حد حجم غير موجود، ولم تنشئ مسار رفع جديد.
- **HTML قديم غير escaped:** مثل `$msg` في الإدارة و`extra.size_chart` لبعض المصادر يحتاج allowlist/تعقيم في مراجعة أمنية منفصلة. نصوص UI الجديدة escaped، وعرض محادثات/ملخص الطلب أصبح DOM text آمنًا؛ لم تتغير البيانات المحفوظة.
- **CSV الأدمن:** التصدير داخل تبويب الطلبات يأتي بعد إخراج shell؛ يحتاج مراجعة الاستجابة وعدم اختلاط HTML بـCSV. رابط التصدير القديم بقي كما هو، ولم تضف الواجهة تصديراً جديداً للـledger.
- **سياسة تعديل العمولة:** الدالة `marketer_can_edit_product_commission()` غير موجودة. النظام الحالي يوفّر الحد النقدي `MAX_MARKUP_AMOUNT`، بينما `MAX_MARKUP_PCT` له مسارات أخرى؛ لم تُختلق صلاحية أو قاعدة مالية جديدة.

## ما لم يُختلق

لا endpoints/حقول حفظ موجودة للـslug أو نشر/مسودة أو رفع لوجو/غلاف متجر، أو headline/benefits مخصصة للاندنج، أو عناوين حساب وتغيير كلمة مرور مستقل، أو محرّر variants/SEO كامل. لذلك لم تظهر أدوات حفظ وهمية أو أزرار ذات أثر جديد. الموجود نُظّم وحُسّن في مكانه.
