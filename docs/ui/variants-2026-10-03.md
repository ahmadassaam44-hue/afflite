# Colour/size orders and portable saved commission — 2026-10-03

## Request and scope

Retain **both** the selected colour and size for customer/marketer orders from products, landing pages, the main shop, created shops and cart checkout; show them in admin and the relevant store owner's private orders. Saved marketer commission must remain included in a landing page's **sale price** in a fresh/incognito browser, not just in the owner's session.

This is a narrowly authorized functional repair, not a changed pricing model or a new store/variant editor. Production remains plain PHP, CSS and Vanilla JS with no hosting build step.

## Reproduced causes

Against the isolated preceding deployment (`d921b95`):

1. Product fallback colour and size buttons shared one global `.vbtn.on` selection. Selecting a colour removed the selected size; `pickV()` returned only the colour.
2. Several callers passed `landing_page_url()` arguments in the wrong order. The copied link carried `ref=vendoor` rather than the marketer code and put the commission in the platform argument.
3. Landing JS replaced the address with `?id=...` only. After saving a synthetic 50 commission, the original session saw 300 (250 base + 50); opening that cleaned address in another browser context saw 250.

Tracing also found that the saved-store "طلب لعميل" payload omitted colour/size options and cart identity truncated variants at 60 characters despite storing 120.

## Changes

- Separate product colour/size selection state and hidden fields; the latest detailed radio/group selection is authoritative. Grouped and Angazny model/colour/size choices initialize the shared dialog correctly.
- Named `color` / `size` dialog fields and a final pre-submit synchronization. Landing inline orders send the same structured values. Opening another product resets absent options rather than leaking previous selections.
- `orders.php` and `checkout_cart.php` store the two bounded metadata fields alongside the existing `variant`. Pure helpers preserve legacy descriptions, recognize old labelled variants and show extra model/package descriptions without repeating the colour/size tuple. The existing Angazny model is also retained if colour/size changes inside the dialog.
- Cart identity uses the complete bounded selection rather than its first 60 characters. Existing cart keys remain usable when matching/merging an old line; different sizes no longer collapse into one line. Checkout copies both choices and displays them in its summary.
- Admin/marketer order rows visibly label **اللون والمقاس**, rather than hiding this column under collapsed extra details. Existing customer order display/export payloads retain the same metadata. The authenticated shop owner gets one **طلبات متجري** link to the existing private order screen; public visitors and other marketers get no owner controls/customer-order data.
- Correct positional link arguments. The cleaned address uses the already-supported `store` alias to keep portable marketer context, retains the product platform, explicit commission (including zero), campaign parameters and hash. Persistent `marketer_stores.json` remains the commission source when no explicit commission is present; precedence/calculation rules were not changed. Explicit zero-commission previews no longer fall back to an older saved positive amount.
- Fix two narrow UI issues found during regression: an expanded mobile variant table no longer keeps the old clipping height after its overflow is changed; dynamically chosen landing CTA contrast no longer animates through an unreadable intermediate grey.
- Refresh the shared asset version to `20261003-variants1`.

**Previously shared ID-only links cannot identify which marketer's price to use in a new browser. Copy a new landing link after saving.** A generic product link still has the generic base price; private profit breakdowns are not added to the buyer-facing landing UI.

### Limits

Previously documented unrelated backend/security/financial defects remain out of scope.
