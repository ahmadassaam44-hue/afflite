# تقسية الأمان والتخزين — 2026-11-23

حزمة إصلاحات بعد مراجعة تقنية شاملة للريبو. بدون أي تغيير في شكل الموقع أو منطق الأسعار والعمولات.

## التغييرات

1. **حذف ملفات التشخيص من الويب**: `debug.php` و `test.php` و `test2.php` و `hello.html` اتمسحت من الريبو.
   - `debug.php` كان بيعرض معلومات داخلية (حالة الإعدادات وعدد الكتالوجات) لأي زائر، وبدون أي حماية.
   - الـ root `.htaccess` بقى فيه `FilesMatch` بيمنع الوصول لأسماء ملفات التشخيص دي حتى لو اترفعت بالخطأ،
     وخطوة الرفع في `updater/update_catalog.py` بقت بتمسحها من السيرفر (`ftp.delete`) — طبقتين حماية.
   - `check-site.yml` بقى يفحص `ping.php` بدل `test2.php`.

2. **كتابة JSON ذرّية**: `jsave` و `jupdate` بقوا بيكتبوا لملف مؤقت ثم `rename` (ذرّي على لينكس).
   - قبل كده الكتابة كانت في نفس الملف (`ftruncate` + `fwrite`): لو العملية اتقتلت في النص (حدود الاستضافة
     المشتركة 60 ثانية / 256MB) الملف كان ممكن يتقطع ويتفسد.
   - القفل اتنقل لملف جانبي `<name>.lock` بيثبّت تسلسل قراءة-تعديل-كتابة رغم الـ rename.
   - مسار الـ fallback اللي كان بيكتب **بدون قفل** لو `fopen` فشل اتشال: دلوقتي بنفشل بوضوح ونسجّل في error_log.
   - تنظيف تلقائي نادر للملفات المؤقتة القديمة (`jatomic_gc`).
   - ملفات `.lock` و `.tmp.*` اتضافت للـ `.gitignore`.

3. **توكن قياس الأداء اتشال من الكود**: `WF_PERF_TOKEN` مبقاش له قيمة افتراضية في Git.
   يتعرّف في `secrets.php` على السيرفر لو احتجناه، وبدونه نقطة `?perf=` مقفولة تماماً.

4. **حماية `assets/manual`**: قاعدة الـ rewrite اللي بتمنع تنفيذ السكربتات في `assets/uploads`
   بقت تغطي `assets/manual` كمان.

5. **CI موسّع** (`lint.yml`): فحص صياغة **كل** ملفات PHP (كان ملفين بس)، فحص صياغة `assets/ui.js`،
   اختبار تخزين JSON الذرّي على PHP حقيقي (`tests/storage_atomic.php`) بما فيه اختبار تزامن
   بأربع عمليات متوازية، وتشغيل اختبارات البايثون.

6. **حارس ما قبل الرفع**: `update-catalog.yml` بقى يفحص صياغة كل ملفات PHP قبل أي رفع FTP،
   فمستحيل نشر كود فيه خطأ صياغة يعطّل الموقع.

7. **`deploy-fix.yml`**: مبقاش بيرفع ملفات التجارب المحذوفة.
