# إصدار تلقائي للأصول (CSS/JS) — الجلسات القديمة تشوف التعديلات فورًا — 2026-10-21

## سؤال الإدارة

> «الناس اللي فاتحة الموقع في جلسات سابقة — هيتنزل عندها التعديلات علطول؟»

## الإجابة المختصرة

| الحاجة | توصل للزائر القديم إمتى؟ |
|---|---|
| الصفحات نفسها (HTML) والأسعار والمنتجات | **أول تحميل/ريفريش للصفحة** بعد النشر — الصفحات `Cache-Control: no-store` فمفيش تخزين في المتصفح خالص، والأسعار بتتحسب على السيرفر مع كل طلب |
| سلة المشتريات | بتتعاود التسعير **تلقائيًا كل طلب** (`cart.php` بيعيد تطبيع كل عنصر عبر `server_order_line`) |
| الطلب نفسه | سعره بيتحسب على السيرفر **لحظة الضغط** — مستحيل يتسعر بسعر قديم |
| ملفات CSS/JS | كانت **ممكن تقدم نسخة كاش قديمة** — دي كانت الفجوة الوحيدة، واتصلحت دلوقتي (تحت) |
| ترتيب «أحدث المنتجات» على الرئيسية | كاش سيرفر 10 دقايق (`home_window_*.json`) — بحد أقصى 10 دقايق بعد تحديث الكتالوج |
| وصول الكود للاستضافة أصلًا | دقائق بعد الدمج على `main` (workflow النشر بيرفع FTP مع حدث push) |

التاب المفتوح من غير ريفريش مفيهوش تحديث حي (مفيش websocket/service worker) — أول ما الزائر
يعمل ريفريش أو ينقل لأي صفحة بياخد كل حاجة جديدة.

## الفجوة اللي كانت موجودة واتصلحت

كل الصفحات كانت حاطة **إصدار يدوي ثابت** في رابط الأصول:

```html
<link rel="stylesheet" href="assets/style.css?v=20261013-row-fix">
<script src="assets/ui.js?v=20261018-visfeat" defer></script>
```

وآخر تعديلين على الأصول اتنشروا **من غير رفع الإصدار**:
- `assets/ui.js` اتعدل في إزالة notice الديالوج (PR #5) — الإصدار فاضل `20261018-visfeat`.
- `assets/style.css` اتعدل في شارات السايدبار (PR #7 — `.side-count`) — الإصدار فاضل `20261013-row-fix`/`20261014-redeploy`.

النتيجة: أي زائر من جلسة سابقة متخزن عنده CSS/JS قديم كان هيفضل شايف النسخة القديمة
(مثلاً شارات الأدمن الحمراء من غير تنسيق `.side-count` الجديد) لحد ما يعمل hard refresh.

### الحل: `wf_asset_v()` — الإصدار هو mtime الملف نفسه

```php
function wf_asset_v($name) {
    static $memo = [];
    $name = basename((string)$name);   // أي مسار غريب بيتقلع لاسم الملف بس
    if (!isset($memo[$name])) {
        $f = __DIR__ . '/assets/' . $name;
        $m = is_file($f) ? (int)@filemtime($f) : 0;
        $memo[$name] = (string)($m > 0 ? $m : 20261021);
    }
    return $memo[$name];
}
```

- **كل الـ33 مرجع** لـ `style.css` / `ui.js` / `tracker.js` في 15 ملف بقوا بيطبعوا
  `wf_asset_v(...)` — أي نشر بيغيّر mtime الملف على الاستضافة ⇒ الرابط نفسه بيتغير
  ⇒ المتصفح بيسحب النسخة الجديدة **من أول تحميل صفحة** من غير hard refresh ولا bumps يدوية.
- الملفات اللي مااتغيرتش بتحتفظ بنفس الإصدار فالكاش العادي بيشتغل (مفيش إعادة تحميل بلا سبب).
- سياقات الاستدعاء: `<?= wf_asset_v('style.css') ?>` في قوالب HTML، ودمج نصّي
  `' . wf_asset_v('style.css') . '` جوّه سلاسل `echo` (dashboard/layout.php، صفحة رفض CSRF في
  config.php، بلوك الـ404 في landing.php).
- `error.php` صفحة مستقلة (ما بتحمّلش config.php) ⇒ بتستخدم `@filemtime` مباشرة inline.
